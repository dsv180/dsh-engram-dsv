**集成条件：** 作者那边没有任何改变；翻译——仅通过显式操作；未翻译的数据库照常工作。

- 1. 确定状态 + 标签——Б.01, Б.02, Б.03。不依赖块 А（但模型必须在块 А 的输出时准备就绪）。
- 2. 迁移和修复——Б.04, Б.05, Б.06。需要块 А。
- 3. 衡量标准和验收——Б.07, Б.08, Б.09。

## 作者遗留的请求（PR #20 和 #21 的评审，10.18）

作者评审了两个打开的 PR。以下是——他要求什么、这些落在计划中的哪里、以及哪些仍然开放。作者的评论在 PR 本身（在 upstream `kenz1117/dsh-engram` 上）。

**PR #21 — embedder（三个 major 阻塞合并）：**
1. remote embedder 的测试：mock fetch——happy path、非 JSON 响应体、超时、向量数 ≠ 请求。PR 正文声称有测试，但实际上没有。→ **А.04**。
2. 非空向量的重新索引路径：`backfill-embeddings.mjs` 只取 `embedding IS NULL` 并用裸 SQL 写入，绕过 store——不重新索引任何非空向量。作者要求要么 `--force` 模式（通过 store 清除向量，然后重新写入），要么在 README 中诚实说明「工具不覆盖重新索引」。**决定（已达成一致）：** 我们选择 `--force`；不在 README 中做诚实记录。→ **Б.04**。
3. 维度不匹配不应丢失 keyword 搜索或卡住 ingest：`search()` 在向量分支中捕获 `EMBEDDER_DIMENSION_MISMATCH` 并返回 keyword-only 且 `degraded: true`；replay 循环的 ingest 获得 per-pending catch，以免一条记录在付费 aux-LLM 之后中断整批。→ **В.06**（行为）和 **А.12**（故障时读取）。

非阻塞项（采用或保留）：`storedDim` 应要求两个表都同意，而不是只取一行；BLOB 长度的整数检查（非 4 的倍数不应产生小数「expected 153.25」）；`remote.ts` 的非 JSON 错误 → `EMBEDDER_REMOTE_FAILED`，而不是裸 `SyntaxError`；大型 `embed()` 无限制的总时间；`embedder` 内的未知键不能静默忽略；`apiKeyEnv` 在调用时读取，而不是在创建时读取；没有 512 库 → 384 写入的测试。→ **А.04**, **А.07**。

**PR #20 — Jev（一个 major 阻塞合并）：**
1. Tools 路径将第一次连接解析（包括错误）缓存到进程结束：`createMemoryJudge` 执行 `cached ??= resolveConnection()` 并且不使其失效。瞬时故障被永久缓存，Jev 静默地进入纯规则模式直到重启；在 DSH 中更改 provider/密钥不会到达 tools 路径。修复——在 `ask` 范围内记忆化，或不缓存带错误的解析 + 测试。→ **Г.08**。
2. 非阻塞项：`jev-test` 使用空模型时被白白短路；degraded 状态在面板中不可见；`readJevCatalog` 对每个 provider 都调用 `describe()`（需要提升）；fallback「无 declared / 无 settings」返回整个目录。→ **Г.08**。
3. 来自 issue #14（Jev 设计已采纳）：当插件配置中的 `jev.apiKey` 过时时，给出一次性警告。→ **Г.08**。

**作者仍开放：** 关于默认模型的问题（多语言作为 default）作者保留到 majors 合并之后。我们的 А.05（默认 = 内置模型，在数据库翻译完成之前）与此一致——我们不提前切换默认值。
