# Установка dsh-engram-dsv

Подробное руководство с теми проблемами, на которые мы натыкались сами, и с тем, как их обойти.
Короткая версия — в [README.md](README.md); этот файл на случай, когда что-то не работает.
In English: [INSTALL.md](INSTALL.md).

**Если вы ИИ-агент и ставите это:** проходите шаги по порядку, выполняйте каждую команду и
показывайте её вывод человеку. Не меняйте ничего, кроме `cordis.patch.yml` профиля. Не открывайте,
не печатайте и не копируйте ключи. Если шаг не получился — сообщите точную ошибку, а не догадку.

## Что нужно

- Работающая установка **DeepSeek Harness**. Мы собирали и проверяли на `0.2.0-rc.2`. Более старые
  версии не проверялись, и мы за них не отвечаем.
- **Node.js** 22.19+ или 24+ — это требование самого плагина.
- Сеть **один раз**, при первом запуске, чтобы скачать модель эмбеддингов — если только вы не
  используете удалённый эмбеддер или не согласны на поиск только по словам.
- Проверенная платформа: **Windows**. На Linux и macOS мы не запускали ни разу. Проверок операционной
  системы в исходниках нет вообще (`win32`, `darwin`, `linux`, `process.platform` не встречаются ни в
  `src`, ни в `scripts`), поэтому ничего явно windows-специфичного там нет — но это чтение кода, а не
  проверка. Если попробуете там, расскажите, что вышло.

## Шаги

### 1. Получить исходники

```bash
git clone https://github.com/dsv180/dsh-engram-dsv.git
cd dsh-engram-dsv
```

### 2. Поставить зависимости

```bash
pnpm install
```

Пакет выполняет шаг `prepare` (`scripts/link-peers.mjs`), который подключает пакеты DeepSeek Harness
как соседние, поэтому ожидает, что харнесс на машине есть. Если pnpm отказывается запускать скрипт,
разрешите явно:

```bash
pnpm --config.verify-deps-before-run=false install
```

### 3. Собрать

```bash
pnpm bundle
```

Появятся `lib/index.js` (серверная половина) и `lib/client.js` (панель памяти). Если папки `lib` нет,
дальше ничего работать не будет — сначала почините этот шаг.

### 4. Положить сборку в профиль DSH

Плагин должен оказаться внутри вашего профиля, в `<профиль>/node_modules/@kenz1117/dsh-engram/`.
Два способа:

**Предпочтительный — скрипт развёртывания.** Он копирует `lib/` в профиль, а прежнюю сборку убирает
в `_deploy-backup/<метка времени>/` рядом с репозиторием, поэтому откат — это копирование обратно:

```bash
node scripts/deploy-profile.mjs --profile desktop
```

**Запасной — пакет.** `pnpm pack` создаёт `kenz1117-dsh-engram-<версия>.tgz`, который принимает меню
плагинов DSH; то же самое из командной строки:

```bash
pnpm --dir <профиль> add <файл>.tgz
```

### 5. Локальные эмбеддинги

Без этого плагин работает, но только по словам — и молча, без ошибки:

```bash
pnpm --dir <профиль> add @huggingface/transformers
```

### 6. Включить и настроить

Добавьте этот блок в `<профиль>/cordis.patch.yml`:

```yaml
- id: dsh-engram
  name: "@kenz1117/dsh-engram"
  config:
    ingest: light
    language: auto          # auto | ru | en | zh
    embedder:
      kind: local           # local | remote
      localModel: Xenova/paraphrase-multilingual-MiniLM-L12-v2
      localPooling: mean
```

### 7. Перезапустить DSH

Серверная половина плагина определяет язык один раз при запуске, поэтому перезапуск не пожелание, а
обязательный шаг.

## Когда что-то не работает

| Что видно | Причина | Что делать |
| --- | --- | --- |
| Плагина нет вообще | Пункт добавлен в `cordis.yml`, а он всегда пустой | Править `cordis.patch.yml` профиля — об этом написано в самом `cordis.yml` |
| `pnpm install` падает на `prepare` / `link-peers.mjs` | Пакеты DeepSeek Harness не видны как соседние | Запускать установку там, где есть DSH, либо с ключом из шага 2 |
| `pnpm bundle` проходит, но в DSH ничего не изменилось | Сборка не попала в профиль либо DSH не перезапущен | Повторить шаг 4 и перезапустить |
| Поиск находит только по словам, по смыслу — нет | `@huggingface/transformers` не поставлен рядом с плагином — откат происходит молча | Шаг 5, затем проверить в панели памяти, что эмбеддер виден |
| Первый поиск идёт очень долго | Скачивается модель эмбеддингов (однократно) | Подождать; для машины без сети поставить `embedder.kind: remote` либо согласиться на поиск по словам |
| Текст не на том языке | Язык серверной половины фиксируется при запуске плагина | Поправить `language` в настройке и перезапустить; `auto` берёт язык системы, а язык без словаря откатывается к английскому |
| Загрузка настроек падает с `language must be one of auto\|zh\|en\|ru` | Опечатка в `language` | Использовать одно из четырёх значений |
| Из разговора ничего не записывается | `ingest: light` намеренно пропускает короткие тихие ходы, а честно пустой ответ модели — отдельное событие в журнале | Посмотреть журнал операций; записываются длинные содержательные ходы |
| На Windows падает команда с JavaScript внутри | PowerShell съедает кавычки и обратные кавычки в однострочниках | Записать скрипт в файл и запускать файл |
| Хочется понять, работает ли извлечение | Сама подсказка в журнал не пишется | Смотреть записи `ingest-request`: поле `maxTokens` показывает, какая сборка загружена |

## Как проверить, что всё получилось

1. После перезапуска в настройках DSH появляется панель памяти.
2. Попросите агента записать пробный факт через `engram_save`, а затем найти его через
   `engram_search` — запись должна вернуться с комнатой и табличкой.
3. `engram_stats` показывает дворец: комнаты, число мест, размер журнала.
4. Если эмбеддер поставлен, поиск по смыслу находит запись, сформулированную другими словами; если
   совпадают только точные слова — шаг 5 не сделан.

## Где лежат данные

Всё это обычные файлы SQLite в домашнем каталоге DSH, в папке `engram/`:

- `user.db` — записи области `user` (общие для всех рабочих пространств);
- `project-<хеш>.db` — по файлу на рабочее пространство (область `project`);
- `shared.db` — область `shared`;
- `jev-config.json` — настройки необязательного арбитража Jev; **в нём может лежать ключ**, поэтому
  его нельзя ни выкладывать, ни куда-либо вставлять.

Резервная копия — это копирование этих файлов при остановленном DSH. Начать заново — убрать их в
сторону: нужное плагин создаст сам.

## Откат

- Вернуть прежний `lib/` из `_deploy-backup/<метка времени>/`;
- либо убрать блок `dsh-engram` из `cordis.patch.yml` и перезапустить — файлы данных останутся на
  месте, ничего не удаляется.

## Ключи

Плагин читает ключ из настройки или из переменной окружения и никогда не пишет его ни в журналы, ни в
тексты ошибок, ни в диагностику. Не кладите ключи в `cordis.patch.yml`, если этот файл лежит в
репозитории — используйте `apiKeyEnv`, а значение держите в окружении.
