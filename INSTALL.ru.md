# Установка dsh-engram-dsv

Подробное руководство с теми проблемами, на которые мы натыкались сами, и с тем, как их обойти.
Короткая версия — в [README.md](README.md); этот файл на случай, когда что-то не работает.
In English: [INSTALL.md](INSTALL.md).

**Если вы ИИ-агент и ставите это:** проходите шаги по порядку, выполняйте каждую команду и показывайте
её вывод человеку. Не меняйте в профиле ничего, кроме `cordis.patch.yml` и `pnpm-workspace.yaml`. Не
открывайте, не печатайте и не копируйте ключи. Если шаг не получился — сообщите точную ошибку, а не
догадку.

Две вещи, на которых спотыкаются чаще всего:

- сборка (`pnpm bundle`) обязательна — без неё в пакете нет `lib/`, и DSH молча получает нерабочий плагин;
- запись за пределы рабочей папки обычно запрещена песочницей агента, а профиль DSH лежит именно там —
  развёртывание потребует разрешения человека (раздел «Песочница и права»).

## Что нужно

- Работающая установка **DeepSeek Harness**. Мы собирали и проверяли на `0.2.0-rc.2`; более старые
  версии не проверялись, и мы за них не отвечаем.
- **Node.js** 22.19+ или 24+ — требование самого плагина (`engines` в его `package.json`).
- **pnpm — тот, что поставляется с DSH**, а не сторонний: профиль ведёт именно он, и чужой pnpm может
  рассогласовать `pnpm-lock.yaml` профиля. Поставляемый pnpm лежит в
  `<DSH>\resources\runtime\pnpm\bin\pnpm.cjs`, рядом — свой Node в `<DSH>\resources\runtime\`. Вызвать
  его с явным путём безопасно: это та же версия, которой DSH управляет профилями. В `PATH` pnpm может
  не быть вовсе.
- **Сеть один раз**, при первом запуске — скачать модель эмбеддингов. Если только вы не выбрали удалённый
  эмбеддер или не согласны на поиск только по словам.
- Проверенная платформа: **Windows**. На Linux и macOS мы не запускали ни разу. Проверок операционной
  системы в исходниках нет вообще (`win32`, `darwin`, `linux`, `process.platform` не встречаются ни в
  `src`, ни в `scripts`), поэтому ничего явно windows-специфичного там нет — но это чтение кода, а не
  проверка. Если попробуете там, расскажите, что вышло.

Дальше `<DSH>` — каталог установки DeepSeek Harness, `<профиль>` — имя профиля (обычно `desktop`).

## Маршрут

`git clone` → `pnpm install` → `pnpm bundle` → `pnpm pack` → `dsh plugin --profile <профиль> add <файл>.tgz`
→ правка `cordis.patch.yml` → проверка. Сборка и упаковка — не формальность: маршрут
`dsh plugin add github:...` скачает исходники и выполнит `prepare`, но **не соберёт** `lib/`, поэтому
привезёт нерабочий плагин.

### 1. Получить исходники

```bash
git clone https://github.com/dsv180/dsh-engram-dsv.git
cd dsh-engram-dsv
```

### 2. Поставить зависимости

```powershell
& "<DSH>\resources\runtime\node\node.exe" "<DSH>\resources\runtime\pnpm\bin\pnpm.cjs" install --config.verify-deps-before-run=false
```

Пакет выполняет шаг `prepare` (`scripts/link-peers.mjs`) — он подключает пакеты DeepSeek Harness как
соседние. Если в выводе сказано, что все 19 пакетов пропущены, — это нормально: на машине с уже
установленным DSH они находятся иначе, и на сборку это не влияет. Ключ
`--config.verify-deps-before-run=false` снимает отказ pnpm запускать скрипты пакета.

### 3. Собрать

```powershell
& "<DSH>\resources\runtime\node\node.exe" "<DSH>\resources\runtime\pnpm\bin\pnpm.cjs" bundle
```

Появятся `lib/index.js` (серверная половина) и `lib/client.js` (панель памяти). **Если папки `lib` нет,
дальше ничего работать не будет** — сначала почините этот шаг.

### 4. Собрать пакет

```powershell
& "<DSH>\resources\runtime\node\node.exe" "<DSH>\resources\runtime\pnpm\bin\pnpm.cjs" pack
```

Рядом с репозиторием появится `kenz1117-dsh-engram-<версия>.tgz` — это то, что ставится в профиль.

### 5. Поставить в профиль

Сначала — про pnpm 11. Он больше не читает `pnpm.onlyBuiltDependencies` из манифеста плагина и считает
пропущенные нативные сборки (`onnxruntime-node`, `protobufjs`, `sharp`) **ошибкой**. Разрешение живёт в
`pnpm-workspace.yaml` **профиля** (в манифесте плагина его не видно, поэтому оно и не действует):

```yaml
allowBuilds:
  - onnxruntime-node
  - protobufjs
  - sharp
```

Затем установка:

```powershell
dsh plugin --profile desktop add "<путь>\kenz1117-dsh-engram-<версия>.tgz" --ignore-scripts
```

Три особенности этого шага, из-за которых он опаснее, чем выглядит:

- **Успех неотличим от бездействия.** Повторный запуск при уже записанной зависимости возвращает `0` и
  ничего не делает. Проверяйте результат не по коду возврата, а по списку бандлов в
  `<профиль>\package.json` (поле `dsh.profile.bundles`) и по наличию каталога
  `<профиль>\node_modules\@kenz1117\dsh-engram`.
- **Прерванная установка оставляет замок** `<профиль>\package.json.lock` (6 байт, внутри — PID процесса).
  Следующая операция ждёт освобождения **121 секунду** и падает с
  `atomic-write: timed out waiting for the writer lock`. Лечится так: закрыть DSH, удалить
  `package.json.lock`, повторить установку.
- **Отказ на нативных сборках оставляет профиль изменённым.** Поэтому сначала `allowBuilds`, потом установка.

Эмбеддер `@huggingface/transformers` объявлен зависимостью плагина, и `dsh plugin add` ставит его вместе
с ним — отдельный шаг не нужен. Он нужен только при ручном развёртывании одной сборки
(`scripts/deploy-profile.mjs`): тогда

```powershell
pnpm --dir "<профиль>" add @huggingface/transformers
```

Без него плагин работает, но только по словам — и молча, без ошибки.

### 6. Включить и настроить

```yaml
- id: dsh-engram
  name: "@kenz1117/dsh-engram"
  config:
    ingest: light
    language: auto          # auto | ru | en | zh
    embedder:
      kind: local           # local | remote
```

Модель эмбеддингов **не указывайте**: она выбирается по языку сама — для китайского родная
`Xenova/bge-small-zh-v1.5` (512 измерений), для остальных языков многоязычная
`Xenova/paraphrase-multilingual-MiniLM-L12-v2` (384). Явно заданная `embedder.localModel` всегда старше
этой подстановки.

**Смена модели не делается одним словом.** У векторов прежней модели другая размерность, а косинус
считается по меньшей длине: смесь размерностей не падает, а тихо портит поиск. При старте плагин сверяет
размерность векторов в библиотеке с размерностью модели и пишет предупреждение в журнал DSH, а в журнал
операций — что именно поднялось (`embedder-ready`). Чтобы исправить, пересчитайте векторы:

```powershell
node scripts/backfill-embeddings.mjs
```

### 7. Включиться

Обычно плагин монтируется сразу после установки, без перезапуска: панель памяти появляется в настройках
DSH сразу, а в начале следующей сессии приходит профиль памяти. Перезапуск нужен в двух случаях: если
панели нет через полминуты — и всегда, когда вы **заменили сборку у уже работающего плагина** (скриптом
развёртывания). Файлы читаются при монтировании, поэтому новый код заработает только при следующем.
Язык серверной половины тоже фиксируется при монтировании.

### 8. Проверить

```powershell
node scripts/check-journal.mjs
```

Скрипт только читает базы и отвечает на три вопроса: какая модель поднялась, идёт ли извлечение, нет ли
смеси размерностей. Дальше — панель памяти в настройках DSH; пробный факт через `engram_save` и поиск его
через `engram_search` (запись должна вернуться с комнатой и табличкой); `engram_stats` — комнаты, число
мест, размер журнала. Если эмбеддер на месте, поиск по смыслу находит запись, сформулированную другими
словами.

## Песочница и права

Если установку выполняет ИИ-агент под песочницей (например, DSH с политикой `workspace-write`), запись
**за пределы рабочей папки запрещена**, а профиль DSH лежит именно там. Признак: развёртывание падает с
`EPERM`, а создание любого нового файла в каталоге профиля — с «Access to the path ... is denied». Это не
занятость файла: чтение из профиля при этом работает. Что делать: человек запускает шаг развёртывания сам
либо разово выдаёт агенту расширенный доступ на эту команду.

## Когда что-то не работает

| Что видно | Причина | Что делать |
| --- | --- | --- |
| Плагина нет вообще | Пункт добавлен в `cordis.yml`, а он всегда пустой | Править `cordis.patch.yml` профиля — об этом написано в самом `cordis.yml` |
| `pnpm install` падает на `prepare` / `link-peers.mjs` | Пакеты DeepSeek Harness не видны как соседние | Запускать установку там, где есть DSH, с ключом из шага 2. Сообщение «все 19 пропущены» — норма |
| `dsh plugin add` вернул `0`, а плагина нет | Зависимость уже записана в профиле: команда не идемпотентна и молча ничего не делает | Сверить `dsh.profile.bundles` в `<профиль>\package.json`; лишнюю запись убрать и повторить шаг 5 |
| Операция ждёт 121 секунду и падает с `atomic-write: timed out waiting for the writer lock` | Прерванная установка оставила замок `package.json.lock` | Закрыть DSH, удалить `<профиль>\package.json.lock`, повторить |
| `dsh plugin add` падает с `ERR_PNPM_IGNORED_BUILDS: onnxruntime-node…` | В `pnpm-workspace.yaml` профиля нет `allowBuilds` (pnpm 11 не читает поле из манифеста плагина) | Добавить `allowBuilds` в профиль и повторить; профиль после отказа остаётся изменённым, так что сначала разрешение, потом установка |
| `pnpm bundle` проходит, но в DSH ничего не изменилось | Сборка не попала в профиль; либо заменили код у работающего плагина | Повторить шаг 5; при замене кода — перезапустить DSH |
| Развёртывание падает с `EPERM`, новый файл в профиле не создаётся | Песочница агента запрещает запись за пределами рабочей папки | Раздел «Песочница и права» |
| Поиск находит только по словам, по смыслу — нет | `@huggingface/transformers` не поставлен рядом с плагином — откат происходит молча | `node scripts/check-journal.mjs`: он скажет, что векторов нет; поставить пакет (шаг 5) |
| Записи есть, а поиск по смыслу врёт | В библиотеке векторы разных размерностей — модель меняли без пересчёта | `node scripts/check-journal.mjs` покажет размерности; пересчитать: `node scripts/backfill-embeddings.mjs` |
| Первый поиск идёт очень долго | Скачивается модель эмбеддингов (однократно) | Подождать; для машины без сети поставить `embedder.kind: remote` либо согласиться на поиск по словам |
| Текст не на том языке | Язык серверной половины фиксируется при монтировании плагина | Поправить `language` в настройке и перезапустить; `auto` берёт язык системы, а язык без словаря откатывается к английскому |
| Загрузка настроек падает с `language must be one of auto\|zh\|en\|ru` | Опечатка в `language` | Использовать одно из четырёх значений |
| Из разговора ничего не записывается | `ingest: light` намеренно пропускает короткие тихие ходы, а честно пустой ответ модели — отдельное событие в журнале | `node scripts/check-journal.mjs`: покажет число запросов, успехов и причины пропусков |
| На Windows падает команда с JavaScript внутри | PowerShell съедает кавычки и обратные кавычки в однострочниках | Записать скрипт в файл и запускать файл |

## Где лежат данные

Всё это обычные файлы SQLite в домашнем каталоге DSH, в папке `engram/`:

- `user.db` — записи области `user` (общие для всех рабочих пространств);
- `project-<хеш>.db` — по файлу на рабочее пространство (область `project`); пустые файлы — норма, а не
  следы неудачной установки;
- `shared.db` — область `shared`;
- `models/` — скачанные модели эмбеддингов;
- `jev-config.json` — настройки необязательного арбитража Jev; **в нём может лежать ключ**, поэтому его
  нельзя ни выкладывать, ни куда-либо вставлять.

Резервная копия — это копирование этих файлов при остановленном DSH. Начать заново — убрать их в сторону:
нужное плагин создаст сам. Журнал операций лежит в тех же файлах (таблица `op_log`) и читается скриптом
`scripts/check-journal.mjs`.

## Откат

- Вернуть прежний `lib/` из `_deploy-backup/<метка времени>/` рядом с репозиторием (развёртывание теперь
  копирует файлы поверх, поэтому обратное копирование — и есть откат; делать при закрытом DSH);
- либо убрать блок `dsh-engram` из `cordis.patch.yml` и перезапустить — файлы данных останутся на месте,
  ничего не удаляется.

## Ключи

Плагин читает ключ из настройки или из переменной окружения и никогда не пишет его ни в журналы, ни в
тексты ошибок, ни в диагностику. Не кладите ключи в `cordis.patch.yml`, если этот файл лежит в
репозитории — используйте `apiKeyEnv`, а значение держите в окружении.
